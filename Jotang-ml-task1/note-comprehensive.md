### 4. batch size
>为什么 batch size 不常取 samples 的约数，而往往取 2 的幂次？
我直觉上认为：如果 batch size 不能整除样本数，最后一个 batch 不完整，虽然不知道有什么影响，反正就是感觉上存在负面效果。

但事实上除非是手写循环/有对 batch 大小敏感的层（比方说只剩下 1 个样本的 batch 算得的方差不好归一化），否则在 PyTorch 的 DataLoader 里，不整除没有任何关系。

因为
1. 模型和损失函数不关心 batch 大小
- nn.Linear 对输入的第一维没有限制，可以是 64，也可以是 56，甚至是 1。
```
Z1 = X_batch @ W1.T + b1
(B, 16) = (B, 2) @ (2, 16) + (16,)
(16,)此处表示没有行列概念的一维张量，里面有 16 个元素，可以视作其中一个维度是 1，然后通过广播加法变化为可加的同型矩阵
```
- nn.CrossEntropyLoss 对 batch 大小也没有限制。
- 反向传播和参数更新同样不关心 batch 大小。

**关于广播**

NumPy 和 PyTorch 中的一种机制：当两个张量形状不同，但满足一定条件时，较小形状的张量会自动扩展成较大形状，然后进行逐元素运算。
    用于把低维的偏置向量应用到高维的每个样本上。
>从右向左逐维比较两个张量的形状：
>- 如果两个维度相等，或者其中一个维度是 1，就可以广播。
>- 如果某个张量维度更少，可以在左边补 1。
总而言之，就是先补个 1 然后拓展到样本数或者本来就符合样本数，以便符合矩阵加法的要求。

*疑问 1*：为什么广播机制可以实现减少内存占用等等？在后续完成广播后，不一样还是把 b 拓展为 B*H 的矩阵了吗？
- 广播的扩展是逻辑上的，不是物理上的。它不会真的创建一个 (B, H) 的新张量存储到物理内存上，内存里仍然只有 H 个浮点数。

那么此时自然地又出现了一个疑问 2：*到底是怎么做到不复制还能计算的呢？这是采取了某种小诡计吗？*
- 物理意义上的张量实际上是一个连续的一维内存块 + 一组元数据，也就是一个内存地址对应一个值。
- 但矩阵计算时并不是按照物理意义上的内存块找的数据，而是按照 stride （沿着某个维度移动一个单位，内存地址要跳过多少个元素）算地址，相当于是**只照着逻辑算出来的内存地址找数据，而不关心物理意义上到底是否存在连续的内存块。**
- 广播机制就是让 stride = 0, 让某个维度上的多个逻辑索引映射到同一个内存地址。*总而言之就是在物理上不占用内存的前提下，骗过了逻辑计算。*

2. DataLoader 默认 drop_last=False, 也就是不丢弃不完整的 batch。

*疑问 3：为什么堆叠成 Batch 可以提高运算速度？*
GPU 擅长并行处理大批量的矩阵计算，所以堆叠为适量的 batch，可以提高 GPU 并行利用率，同时也减少每一次 GPU 操作启动 CUDA 内核的启动耗时。

# #1 机器学习中的基本概念

### 关于函数、类、模块、包、库、框架的关系
- 函数：可复用、不存储状态的操作，类似于一小段脚本？
- 类：一种自定义的数据类型，把数据和操作数据的方法打包在一起。也就是一种定义属性和函数的模板。
- 实例：按照“类”这个模板创造出来的具体对象，可以调用函数，可以储存状态。
- 属性：也可以叫状态，对象里保存的数据，可以是数字、字符串、列表等普通数据，也可以是其他对象，比如 nn.Linear、nn.Sequential
- 方法：相当于对象中的函数。
- 模块：一个 Python 文件，可包含函数、类、变量。
- 库：一组相关模块的集合
>与经典 hello world 程序中的 return 0 不同，return 0 是说的返回状态码交给操作系统，表示程序成功，可以使用`$?`查看；而这里 return self.net() 实际上是返回这个方法得到的值，让调用者接收这个值。

### 基本概念释义
1.  `make_moons`：是`scikit-learn`提供的一个数据集生成器，可以直接生成两个互相交错的半圆形数据，也就是所谓的 two interleaving half circles（二个交错的半圆）。它专门适合用于演示分类和聚类。

2. 数据泄露：指的是在数据处理过程中，由于错误操作，机器意外学习了验证集和测试集里的数据，最终导致得到的验证/测试结果与实际模型能力不符，类似于考试中的*泄题*。

3. ReLU
Rectified Linear Unit，修正线性单元
ReLU(x) = max(0, x)：输入的正数保持不变，负数变成 0.
>为什么需要激活函数？
如果没有可以非线性处理的激活函数，那么从线性的全连接层组合到另一个线性的全连接层，仍然只是一个线性变换。

4. logits
由前面模型分析得到的，尚未经过 Softmax 转换的原始分数。大概是一种类似于呈现支持力度的分数，
>模型是如何得出 logits 的？
后续需要使用`CrossEntropyLoss`这个损失函数，所以需要没有 Softmax 处理的 logits，直接输入CrossEntropyLoss.

>Softmax 是什么？归一化有什么用？
Softmax 可以把多个原始分数转换成概率分布形式。归一化相当于把不同尺度的数值转换到一个统一的、可比较的范围（大概是让分布差异更加直观？


5. init_weights
```python
def init_weights(m):
if type(m) == nn.Linear:
nn.init.normal_(m.weight, std=0.01)
```
在训练开始前先给模型参数一个初始值。
- `(m)`表示`apply()`当前传给`init_weights`的一种模块。
- `if type(m) == nn.Linear:`只有当前模块是`Linear`时，才初始化它的权重。
- `nn.init.normal_()`
normal 是指正态分布，也就是说从一个正态分布中随机生成初始权重。std 就是 standard deviation，正态分布中的标准差。
>为什么这里有下划线？
`_`表示 in-place operation 原地操作，也就是直接修改原来的 Tensor，而不是创建一个新的 Tensor 再替换（`_`类似于 bash 中的`source`？
>`nn.init.normal`不是在调整权重吗？和替换/创建 Tensor 有什么关系？
>`m.weigh`是什么？为什么没有`m.bias`？
`m.weight`本质上是一个parameter，
对于`bias`，不是没有`m.bias`，只是`nn.Linear`本身已经有默认参数初始化，所以不需要写在程序里。


>为什么要设置`if type(m) == nn.Linear:`？为什么需要初始化？初始化为什么不是都设置为 0 吗？
    1. 因为模型训练开始之前：weight、bias必须有数值。否则 Linear 连计算都无法进行。
    2. 如果所有权重都初始化为0，那么这一层所有神经元的输出都一样，反向传播时梯度也完全相同。那么神经元所学到的东西就无法真正分化，所以必须用随机数（如 Xavier 或 Kaiming 初始化）来打破对称性。

6. `net.apply(init_weights)`
把 `init_weights` 应用到 `net` 及其子模块。
>这里的`net`就是前面自定义的`nn.Sequential()`是吗？可是`net`下面的定义并不含`apply`，`apply`是自定义的还是本来就有的？
apply 不是自定义的，是 PyTorch`nn.Module` 自带的方法。


>写`net[0].weight`又是什么意思？
意思是取 net 中第零个子模块研究它的 weight.

>如果写`net = make_net(16)`，Python 解释器怎么确定这里的16指的是`hidden_units`？就因为之前写的是`net = make_net(hidden_units)`，所以后文写16/32等等就可以识别出来是说hidden_units？
不是，是因为之前写过了`def make_net(hidden_units=16)`，所以Python记住了make_net的第一个参数就是hidden_units，


>为什么 make_net() 最后要 return net？为什么要return net才可以让train.py得到模型？难道这个make_net()的自定义函数不是直接写在程序里的吗？为什么不可以让train.py在调用model时直接调用？那么什么情况下不用写return？这个return和经典的hello.c中的 return 0 有什么区别？
`def make_net`只是在定义一个函数，并不是定义完了以后就能让 Python 自动把它交到其他程序里，真正执行需要用`make_net(hidden_units)`
当我们在写：
```python
def make_net(hidden_units=16):

    net = nn.Sequential(
        nn.Linear(2, hidden_units),
        nn.ReLU(),
        nn.Linear(hidden_units, 2)
    )

    return net
```
函数调用时发生了什么？

事实上是先调用了 make_net 然后进入函数内部，创建 Sequential，再把它放入局部变量 net，return net 函数结束。没有 return net 就是创建好了一个模型，但是并没有把模型交付给最开始调用这个函数的命令。可以直接调用写`net = model.make_net`，如果调用函数者不需要返回值，比如说只是执行一个动作，那么也可以不加return。C 中的 return 0 实际上是返回状态数 0，证明程序成功。而 Python 中想要设置程序进程，通常需要exit()等等。

- shuffle=True：训练时每个 epoch 打乱顺序。

*疑问*：为什么训练集是`shuffle=True`，验证集和测试集是`shuffle=False`？
>一般情况下，训练集为了保证 DataLoader 每轮读取训练样本时的随机性当然是打乱更好。
>而验证集不参与参数更新，所以没有必要打乱，而且每次都按照固定顺序检查，更能有效比较出来训练效果。
>测试集：如果每次测试都重新随机排列，虽然总体的 accuracy 一般不会因此改变，但样本顺序变了不利于调试和定位具体错误样本。

# #2 定义模型
```python
class MLP(nn.Module):
    def __init__(self, hidden_units=HIDDEN_UNITS, num_classes=2):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(2, hidden_units),
            nn.ReLU(),
            nn.Linear(hidden_units, num_classes))

    def forward(self, x):
        return self.net(x)
```
### 继承
1. 定义一个类 `MLP`，让它继承 nn.Module 的 PyTorch 管理参数、切换训练/评估模式、保存/加载状态字典等能力，免得每个方法对应的命令都要自己手写一遍，这种操作大概类似于 C 语言里面写头文件，继承`printf`等能力。

### 初始化
2. `__init__`是类的初始化方法，在创建模型对象时调用。
- `hidden_units=16`：隐藏层神经元数量。默认值是 16。
- `num_classes=2`：输出类别数量。默认值是 2，对应二分类。

3. 调用父类 nn.Module 的初始化方法：`super().__init__()`
具体操作如下：
- 初始化 nn.Module 的内部结构；

- **创建字典**：准备好 _parameters、_modules、_buffers 等容器。
    写`model.net`只能访问`nn.Sequential`对象，而不能把对象里所有的属性名和属性值，一次性列出来。如果让`nn.Module`把子模块存入字典，就可以不用手写巨量`list`+ 具体属性的易错命令，直接写`for name, module in self._modules.items()`就可以遍历所有子模块。
- 相当于字典作为花名册，可以自动全点名。
所以想让`nn.Module`能够透过`net`访问并管理深层的三个层/模型参数等等，最好创建空字典。

- **让注册机制生效**：
关于注册：
把对象加入到一个受管理的集合中，使得 nn.Module 能够统一处理它们。

- [x]疑问： 这里 super() 怎么知道要找的一定是父类的 __init__，不会找到 MLP 的 __init__？

`super`从当前类（MLP）在 MRO（Method Resolution Order，方法解析顺序）中的下一个类开始查找。那么当前类是`MLP`，所以找到的下一个类就是`nn.Module`
- super 的往下一类找的调用方式，就是为了防止这里 super 调用新定义的__init__，然后又进入到super().__init__()，继续重复调用的死循环里。


4. `self.net = nn.Sequential(...)`
此处创建了一个 nn.Sequential 对象，并且把它赋值给了`self.net`，触发 `nn.Module.__setattr__`，将其注册到`self._modules`这个字典中，使得`nn.Module`能管理它。

补充知识：
`__setattr__` 是 nn.Module 重写的方法。当你给 self 的属性赋值时，它会自动检查：
- 如果值是 nn.Module 的子类实例，就放进 self._modules 字典。
- 如果值是 nn.Parameter，就放进 self._parameters 字典。

这样的具体分类，有利于后续对不同属性进行不同处理：
- 子模块，内部可能还有需要细分的子模块、参数等等，需要递归遍历，如这里的`nn.Sequential`。
- 可学习参数，需要交给优化器，如 weight、bias。
- 需要保存但不更新的状态，如 BatchNorm 的 running_mean。
- 普通数据，不需要管理，如 learning_rate、name。

5. forward 定义了前向传播：输入数据 x 如何变成输出。
return 把得到的数据重新交回给调用者，只负责交出数据，交给谁它是不管的。
- 下面我们写`logits = model(X_batch)`事实上达到了一种类似于变量赋值的效果，也就是接收数据，同时命名。
- x 是输入张量，形状通常是 (batch_size, 2)。
- self.net(x) 会依次经过 nn.Sequential 中定义的三层。返回的是形状为 (batch_size, 2) 的 logits。

3. `torch.cuda.synchronize()` & `reset_peak_memory_stats()`
- CPU 默认异步，也就是说发命令之后不会等 GPU 完成任务以后再发下一个，而是立马返回继续下一个命令。
- 在每个 epoch 开始时，重置显存（GPU memory）峰值，这样统计的就是每个 epoch 里的最大显存占用，而不是整个训练从头到尾的最大显存占用。

4. `time.perf_counter()`
`perf_counter`=`performance counter` 性能计数器（但是只计时间）
精度很高，不受系统时间调整影响

5. `optimizer.zero_grad()`
清空上一轮累积的梯度

*如果不清空梯度会发生什么？*
PyTorch 默认会累积梯度，如果不清空，梯度会叠加，导致更新错误。
为什么梯度会积累？如果积累不清除会发生什么？发生过拟合？
>PyTorch 默认`loss.backward()`是把梯度加到`.grad`上，所以会累计梯度，如果不清除积累，参数更新读取的就是累计后的梯度，更新方向将受到过时数据影响导向错误，而随着梯度越来越大，就需要更大的步长，满足大梯度需要的大更新幅度。

清除了梯度的话，有些优化器需要历史梯度怎么办呢？
>像 Adam、SGD with momentum 确实需要历史信息，但它们不是通过累积 .grad 来实现的。它们在内部维护自己的状态（比如动量、平方梯度），和 .grad 是分开的。.grad 只应该保存当前批次的梯度，优化器内部自己保存历史信息。

是最后一层输出的实数，是模型输出的原始分数，不是概率，没有归一化。
>PS: logits 不直接相关类别占比，大概类似于原始分（？

7. nn.CrossEntropyLoss
关于 reduction：本意是归约，这里控制这个损失函数如何把当前 batch 里每个样本各自的损失，怎么合并成一个总的 loss。
- `reduction='mean'`意思是先对 batch 里每个样本算一个损失，然后对这 32 个损失求平均。

8. loss.backward()
反向传播，从 loss 出发，沿着*计算图*反向计算每个参数的梯度，并将其存到每个参数的 .grad 属性里。

**关于计算图**
前向传播时，PyTorch 自动记录的计算过程。
be like:
```
X_batch
  → Linear 第1层
  → ReLU
  → Linear 第2层
  → logits
  → CrossEntropyLoss
  → loss
```
>关于叶子节点：
树（一种数据结构）结构中，叶子是最末端的节点；在 PyTorch 计算图里，直接创建、而不是由其他张量算出来的张量就叫做在最末端，是叶子节点。（此处相关概念并不完全了解，标记为待探索。）

```
loss    
# 根节点
↓
logits
# 中间节点
↓
weight/bias
# 叶子节点（线性层直接创建出来的）
```
叶子节点是前向传播的起点，反向传播的终点，是参数更新的对象，是`loss.backward()`实际关注`.grad`的对象。

8. optimizer.step()
读取每个参数的 `.grad` 中的梯度，根据优化器的规则调整参数值。

9. 关于一些些需要理解的命令行
```python
        train_loss += loss.item() * X_batch.size(0)
        # 累加各个批次的总损失变为整个 epoch 的损失
        train_correct += (logits.argmax(1) == y_batch).sum().item()
        # 统计预测正确的样本数
        train_total += X_batch.size(0)
        # 利用 X_batch 的第零维长度（也就是一个 batch 的样本数），统计整个 epoch 的样本总数
    train_loss /= train_total
    train_acc = train_correct / train_total
# train_loss 除以总样本数，得到整个 epoch 的平均训练损失。
# train_correct 除以总样本数，得到整个 epoch 的平均训练准确率。
```
>补充知识：
1. 这里的`loss`是之前损失函数算出来的当前 batch 的平均损失。
2. `loss.item()`是一种把标量张量转为 Python 浮点数的方法，
3. `.size(0)`是取第零维的长度。

*疑问*：为什么非要累计成整个 epoch 的损失？不能直接在每个 batch 里求平均吗？
>loss 等图线画的是每个 epoch 的平均值。而每个 batch 的数量不一定一致，假设最后一个 batch 只有 8 个样本，但最后算平均值时，最后一个 batch 的平均损失却和前面 batch 权重一样，这不合理，应当乘以对应样本数作为权重。也就是我们现在所做的，加权（乘了样本数）再加到总损失里，算整个 epoch 的平均值。

4. **详解**看上去很复杂的一条命令：`train_correct += (logits.argmax(1) == y_batch).sum().item()`

train_correct 最终累计的是整个 epoch 的准确预测数。
- `logits.argmax(1)`：在类别维度上取最大值的索引，也就是最终预测出的类别（最终交上去的答案）。
- `.argmax(1)`：表示在第一维（也就是 logits）上找最大值下标（index/索引/位置编号）
- `== y_batch`：和真实标签比较，得到布尔张量（T or F）。
- `.sum()`：统计其中 True 的数量。
- `.item()`：转换成 Python 浮点数，累加为一个表示当前批次预测正确的样本数的浮点数。

5. 关于 train_total 的累加

*疑问*：不是已经知道 N_SAMPLES 等数据了吗？为什么还要手动累加？
>这样累加不依赖最开始的样本划分，只计实际训练使用的样本数。
事实上：设置`drop_last`/`sampler`/`WeightdedRandomSampler`/流式数据等等不知道实际与理论样本数不符的情况下，就非常需要这样实用实计地求样本数了。

6. **损失函数拓展表格**（AI 制）

| 任务类型 | 损失函数 | 核心机制/公式 | 优点 | 缺点/适用场景 |
|---|---|---|---|---|
| 回归任务 | MSELoss 均方误差 | loss = (预测值 - 真实值)^2 | 对大误差惩罚很重 | 对异常值敏感；适合误差近似正态分布的任务 |
| 回归任务 | L1Loss 平均绝对误差 | loss = \|预测值 - 真实值\| | 对异常值更鲁棒；梯度恒定 | 收敛可能慢；适合有噪声、异常值的数据 |
| 回归任务 | SmoothL1Loss / HuberLoss | 小误差时用平方，大误差时用线性 | 结合了 MSE 和 L1 的优点 | 常用于目标检测的边框回归 |
| 分类任务 | CrossEntropyLoss 交叉熵 | 先对 logits 做 Softmax，变成概率，再取真实类别对应的概率，取负对数，最后对 batch 求平均；PyTorch 内部已封装 Softmax，数值稳定 | 二分类、多分类通用；梯度性质好，训练稳定 | 不适合多标签任务；类别极度不均衡时可能偏向多数类 |
| 分类任务 | BCEWithLogitsLoss 带 Logits 的二元交叉熵 | 先对每个 logit 做 Sigmoid，变成概率，再计算二元交叉熵，最后求平均；内部 Sigmoid，数值稳定 | 适合多标签，每个类别独立判断；比手动 Sigmoid + BCELoss 更安全 | 只适合二分类/多标签，不适合互斥多分类 |
| 分类任务 | FocalLoss 焦点损失 | 在交叉熵基础上，降低“容易分类样本”的权重，让模型更关注“难分类样本” | 能缓解类别不均衡；目标检测中常用 | 需要调超参数；PyTorch 没有内置，需要自己实现或找第三方 |

2. 关于显存分析

- reserved（缓存起来的） vs allocated（实际使用的）
PyTorch 为什么要申请一大块显存，而不是按需取用？
>因为向 GPU 申请显存比较慢。PyTorch 为了减少频繁申请的开销（慢和碎片化：显存被反复申请释放，容易切成很多小块，大张量可能放不下），会一次申请一块较大的显存，自己内部管理。用完的张量释放后，显存不会立刻还给 GPU，而是留在 PyTorch 的缓存里，下次直接用。

>什么影响了显存占用（指 reserved）？

| 因素 | 影响 | 说明 |
|---|---|---|
| batch size | 最直接 | batch 越大，输入和中间激活越大 |
| 模型参数量 | 直接 | 参数越多，参数、梯度、优化器状态越大 |
| 模型层数/宽度 | 直接 | 层数越多、隐藏单元越多，中间激活越大 |
| 输入特征维度 | 直接 | 特征越多，输入和第一层激活越大 |
| 序列长度 | 对 NLP 大 | 序列越长，中间激活越大 |
| 优化器类型 | 直接 | Adam 比 SGD 多存一阶、二阶动量 |
| 是否计算梯度 | 直接 | 关闭梯度省显存 |
| 是否保留计算图 | 直接 | `no_grad()` 不建图，省显存 |
| 数据类型 | 直接 | `float32` 比 `float16` 占更多显存 |
| 中间结果是否释放 | 间接 | 有些中间张量没及时释放会占显存 |

*为什么机器会过拟合？为什么反复学习反而学不到通用规律？*

*根本区别：*
- 人类学习：我们追求的是“理解背后的原理”，即使数据有限，我们也能用常识、逻辑、因果推理去补全。
- 机器学习：它只是在调整数学参数，让模型在这批数据上的输出尽量接近标签。它不理解任何东西，它只是在拟合。

>举例（ deepseek 解释）：假设你要训练一个模型，判断一张图片是猫还是狗。训练集只有 10 张图片：5 张猫的图片：都是橘猫，背景都是沙发。5 张狗的图片：都是黑狗，背景都是草地。
>模型训练时，它发现了一个“规律”：“橘色 + 沙发 = 猫；黑色 + 草地 = 狗。”
>这个规律在训练集上完全正确，准确率 100%。但它学到的是真正的规律吗？不是。真正的规律是“猫的耳朵尖、胡须长、瞳孔竖”，但模型没学到这些，它学到了“沙发”和“草地”这两个偶然的特征。
>现在你拿一张草地上橘猫的照片去测试，模型会懵——它根据“草地”判断是狗，但根据“橘色”判断是猫，内部参数打架，最终输出可能完全错误。
>**这就是过拟合。模型没有学到“猫之所以是猫”的本质，而是记住了训练集里的噪声和偶然关联。**

我的总结：
- 也就是说，如果过度反复训练，机器就会记住不属于标签的本质的关联，记住训练集中那些偶然的关联，然后把这种关系赋予更多的权重以期待降低损失。
- 但迁移到验证集和测试集时，这种偶然关联大概率不成立。所以之前记忆的这些偶然因素（其实就是噪声）就学错了，这种错误关联就会让它在测试中的表现不如训练。
- 本质上其实是因为机器没有办法像人类一样初步地筛选学习内容，无法区分噪声和准确数据，只是在不加分辨地分析数据全部特征，然后进行数学上的优化。

#### *一些些奇妙的 idea*: 
关于初始的权重设置：
- 是否可以通过一开始提供对显著相关的权重分配，从而实现减小噪声影响、放大关键数据影响？比如猫狗识别中，在初始设置时就刻意对机器强调识别哪一类特征的关联。

|---|---|---|
| 对角线很大 | 模型整体分类正确率高 | 保持或继续调参 |
| 对角线很小 | 模型欠拟合；训练不足；特征不够；模型容量不足 | 增加模型容量；增加训练轮数；增加特征 |
| 某一类误报多，比如真实 0 常预测成 1 | 模型偏向预测类别 1；类别不均衡；阈值不合适 | 调整类别权重；重采样；调阈值 |
| 某一类漏报多，比如真实 1 常预测成 0 | 模型偏向预测类别 0；类别 1 样本少；模型没学到类别 1 特征 | 增加类别 1 样本；调整类别权重；增加特征 |
| 两类互相混淆都很多 | 特征区分度不够；模型容量不足；边界附近样本多 | 增加特征；增加模型容量；更多数据 |
| 某一类几乎全错 | 标签可能有问题；该类样本极少；模型完全没学到该类 | 检查标签；增加该类样本；调整采样 |
| 训练集混淆矩阵很好，测试集差 | 过拟合；模型泛化差 | 加正则化；早停；更多数据 |
| 训练集和测试集混淆矩阵都差 | 欠拟合；模型太简单；训练不够 | 增加模型容量；增加训练轮数；调学习率 |

3. 错误样本：错误样本分布

| 错误样本现象 | 可能原因 | 可考虑方向 |
|---|---|---|
| 错分点集中在两类交界处 | 边界附近样本天然难分；噪声大；模型容量有限 | 增加数据；增加模型容量；特征工程 |
| 错分点远离边界 | 可能是标签噪声；异常值；数据分布有问题 | 检查标签；清洗异常值；检查数据来源 |
| 错分点集中在某一区域 | 模型在该区域学得不好；该区域样本少 | 增加该区域样本；调整采样；特征工程 |
| 错分点集中在某一类 | 类别不均衡；模型偏向另一类 | 调整类别权重；重采样；增加少数类样本 |
| 错分点两类都有且分散 | 模型整体区分能力不足；特征不够 | 增加模型容量；增加特征；更多数据 |
| 错分点很少且分散 | 模型已经不错；剩余错误可能是噪声 | 可继续调参；检查标签；尝试集成 |
| 错分点很多 | 欠拟合；训练不足；模型太简单；学习率不合适 | 增加模型容量；增加训练轮数；调学习率 |
| 训练集错分少，测试集错分多 | 过拟合；泛化差 | 加正则化；早停；更多数据 |
